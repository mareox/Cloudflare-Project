Architecture Overview

Live — Self-Hosted ZTNA

Cloudflare Access + Tunnel

The origin server runs in a private homelab network. Cloudflare Tunnel creates an outbound-only connection to Cloudflare edge — no inbound firewall rules required. Access validates identity before any request reaches the application.

Live — Identity Provider

Google IdP + Reusable Policies

Google OAuth 2.0 is the upstream IdP. Cloudflare-native reusable policies (allow-testers, allow-saas-users, allow-email-me) model group membership without requiring Google Workspace group claims.

Live — WARP Enrolled

Device Enrolled in Zero Trust

WARP client enrolled into mareoxlan team. All DNS and HTTP traffic from the enrolled device is subject to Gateway policy evaluation. Enrollment restricted by Access policy.

Designed — SaaS + Gateway

Policy Templates in Repo

SaaS Access app (SAML), Gateway DNS (anonymizer/malware block), and Gateway HTTP (Entertainment block with streaming exceptions) are fully specified as deployable JSON with verified category IDs from the live Cloudflare API.

1. Self-Hosted ZTNA — Live Implementation

Access application and policy

The Access application covers tunnel.mareoxlan.com/secure*. Any request to that path redirects to mareoxlan.cloudflareaccess.com for identity verification before Cloudflare proxies the request to the Worker or origin.

curl -sI https://tunnel.mareoxlan.com/secure
# HTTP/2 302  location: https://mareoxlan.cloudflareaccess.com/cdn-cgi/access/login/...

After successful Google OAuth, Cloudflare injects two trusted headers:

  • Cf-Access-Authenticated-User-Email — verified email address
  • Cf-Access-Jwt-Assertion — signed JWT verifiable against the team's JWKS endpoint

Access policy structure

4. Best Practices Applied

Default Deny

Every Access application uses block as the default action. Explicit allow rules are required; there is no implicit permit for authenticated users.

Least Privilege

Separate policies for Admins, Testers, and SaaS-Users. Each role gets access only to the resources it needs. No shared catch-all policy.

Policy-as-Code

All Access policies, group definitions, and Gateway rules are committed as JSON templates in this repository — auditable, reproducible, and reviewable without dashboard access.

Origin Lockdown

The origin server has no inbound public access. Cloudflare Tunnel makes outbound-only connections to Cloudflare edge, eliminating direct origin bypass as an attack surface.

Gateway Rule Ordering

Allow rules are placed at lower precedence numbers than block rules (200 vs. 210) to ensure streaming service exemptions fire before the broad Entertainment block. Order is by design, not accident.

IdP Separation

The identity provider (Google) is decoupled from the policy enforcement layer (Cloudflare Access). Adding a second IdP or migrating to Okta does not require touching application policies.
